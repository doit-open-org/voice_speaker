# 首页功能独立页面设计

## 目标

将首页现有的“更多主播”“录音功能”和背景音乐设置中的“添加/更换背景音乐”从弹层迁移到三个独立页面，同时保持现有分类、试听、选择、录音、背景音乐设置、上传和生成结果流程一致。

本次不重做视觉样式，不改变首页的文本配音、音效设置、停顿设置、我的作品、设备连接和合成配音流程。

## 页面结构

在 `app.json` 中注册以下页面：

- `pages/voiceSelect/voiceSelect`：展示现有主播分类和主播列表，支持试听与选择。
- `pages/recorder/recorder`：展示现有录音界面，支持背景音乐设置、开始录音、停止录音和上传。
- `pages/bgmSelect/bgmSelect`：展示现有背景音乐分类和列表，支持试听与选择。

首页保留背景音乐设置弹窗。弹窗中的“添加背景音乐”和已选音乐的“更换”操作进入背景音乐选择页。

## 首页改动

首页三个入口由切换弹层状态改为 `wx.navigateTo`：

- “更多主播”进入主播选择页。
- “录音功能”进入录音页。
- 背景音乐设置中的“添加/更换背景音乐”进入背景音乐选择页。

首页继续负责加载主播列表和背景音乐列表，并继续保存文本合成所使用的 `voiceCheckInfo`、`activeBgmInfo` 和 `bgmSetDetail`。原有主播列表、背景音乐列表和录音右侧弹层从首页 WXML 与组件注册中移除。

## 页面通信

页面间使用微信小程序 `EventChannel`，避免将一次页面操作写入全局变量或本地缓存。

### 主播选择

首页打开主播页时传入主播列表和当前主播 ID。主播页选择后回传完整主播信息并返回首页；用户直接返回时不修改首页状态。

### 背景音乐选择

调用页打开背景音乐页时传入背景音乐列表和当前背景音乐 ID。背景音乐页选择后回传完整音乐信息并返回调用页。该调用页既可以是首页，也可以是录音页。

首页和录音页收到选择结果后立即更新 `activeBgmInfo`。背景音乐参数只有在用户点击设置弹窗的“确定”后才更新 `bgmSetDetail`。执行“还原”时同时清空已选音乐与已确认参数，防止界面显示未选择但合成或上传仍携带旧音乐。

### 录音页面

首页打开录音页时传入背景音乐列表、当前选择和已确认参数。录音页内复用背景音乐设置组件，并可继续进入背景音乐选择页。

录音页每次确认或还原背景音乐设置时，通过打开录音页时建立的 `EventChannel` 同步回首页。录音停止后由录音页使用当前已确认参数上传文件；上传成功后写入现有 `app.globalData.generate`，再使用 `wx.redirectTo` 进入生成结果页，使结果页返回时仍回到首页。

## 数据加载与生命周期

首页已加载的列表会直接传给新页面。若用户过早进入页面导致列表尚未加载，新页面使用现有请求方法自行加载对应列表，避免空白页面。

主播页和背景音乐页各自创建试听播放器。播放另一条音频时复用当前播放器；暂停、播放结束、播放失败、页面隐藏或卸载时重置播放状态，卸载时销毁播放器。

录音组件在页面销毁时释放录音相关监听；录音中的遮罩和最长三分钟限制保持现状。

## 错误处理

- 列表请求失败：保留页面并显示现有风格的错误提示。
- 音频试听失败：停止播放器、清除播放状态并提示失败。
- 录音失败：关闭录音遮罩并提示失败。
- 上传失败：关闭加载提示，保留录音页和当前背景音乐设置，允许用户重新录音。
- 页面未收到初始化数据：使用空的安全默认值并尝试自行加载列表，不访问不存在的分类项。

## 测试与验收

使用 Node 测试脚本和微信小程序 API 桩验证以下行为：

1. `app.json` 注册三个新页面。
2. 首页三个入口分别导航到正确页面，旧的三个右侧弹层不再渲染。
3. 主播选择页接收当前选择、回传选择结果并返回。
4. 背景音乐选择页可由首页和录音页复用，并正确回传选择结果。
5. 试听播放器在暂停、结束、失败和卸载时正确重置或销毁。
6. 录音页收到、修改并同步背景音乐状态，上传参数使用最新已确认设置。
7. 录音上传成功后进入生成结果页，失败时隐藏加载状态并留在当前页。
8. 新增 JavaScript 文件通过语法检查，项目相关测试全部通过。

最终交付一个包含完整项目与 Git 历史的新版 ZIP，原始桌面 ZIP 不被覆盖。
